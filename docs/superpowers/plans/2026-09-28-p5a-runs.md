# P5a Runs: combat auto-save, run feed and run recap — Implementation Plan

> **For agentic workers:** implement with subagent-driven development: one fresh implementer subagent per task, in an isolated worktree, working test-first; the coordinator (Claude) reviews every task's diff and merges it. This is a **contract plan** (as P3b and P4): it fixes the decisions, file ownership, names, signatures, behavior and the tests each task must add, and leaves the code to the implementer. Research notes with verbatim current code are the implementer's reference for existing APIs (see "Sources").

**Goal:** Make every closed fight survive a restart and make runs readable at a glance (spec §6.3, §8.4, §8.5). A closed combat encounter is saved automatically as a compact summary linked to its run by exact `VisitRef`; an optional setting keeps the full hit detail. The Runs page opens on a day-grouped **feed of run cards** (outcome, time, duration, party, your damage share and rank, loot strip, fame gained, deaths, exalt progress — each only from exact links), with today's archive table kept as the Table view. A **run recap** replaces the workbench text as the way to read one run: tiles plus Damage (meter table, damage over time, damage by source), Loot, Players, Resources, Timeline and Evidence sections. S4 ("open the damage breakdown of the last completed run in ≤ 2 clicks") is met from Home and from the feed.

**Split (user decision, 2026-09-28):** P5 ships as two PRs. **P5a** (this plan): the `encounters` auto-save, Settings › General › Combat history, the run feed and the run recap, S4. **P5b** (planned after P5a merges): the Runs & DPS page with customizable tabs (Feed · Dungeons · Live meter · Recordings), the Live meter moved into its tab (the DPS Logger page becomes a pointer, Alt+8 opens the tab), Recordings, Dungeons cards, Statistics and DPS Logger leaving the sidebar, the remaining filter bars and P1c deferrals, and the S8 timing harness. P5a keeps the page title "Runs" and the sidebar unchanged.

**Architecture:**
- **Wave A (parallel):** the combat summary model, builder and reader (Task 1); run facts for the feed (bag names, fame gained per run, the shared run-outcome rule, portal sprites in the kit) (Task 2); Settings › General with the Combat history settings (Task 3).

- **Honesty (spec §1).** Unknown is never shown as zero: a missing link, an unverified local row, an absent max HP or unavailable incoming damage is "—" or a one-line reason, never 0. Links are exact (`VisitRef` equality, `EncounterContext`, the recording's own fields); no joins by name or time across modules. The only name match allowed is **inside one recording** (a death notification's name against that recording's own player names, only when the name is known and unique there). - **Threading.** The capture producer (`PacketProcessor` thread) only hands closed `DpsData` off; summaries are built and written on a dedicated single worker (never the producer, the EDT or the history I/O worker). Archive reads run off the EDT and are cancelable where the API allows. The EDT only applies immutable models.

The existing runs archive workspace keeps its name `runs` and its component names; the class `tomato.gui.dps.EncounterSummary` keeps its name (the new persisted types use other names, below).
- **Encoding.** Sources are UTF-8; literal `·`, `…`, `‹`, `—`, `×`, `≈`, `#` are fine.

## Decisions recorded for this phase

User decisions (2026-09-28):
- **Split P5 into P5a and P5b** (scope above).
- **The Live meter moves into Runs & DPS** (P5b): the single `DpsGUI` moves into the Live meter tab, the DPS Logger page becomes a pointer, Alt+8 opens the tab. Nothing of this is in P5a.
- **"Keep full combat detail" is included, off by default:** Settings › General toggle; the full detail file is saved without the debug packet log and pruned after 30 days (the day count is a setting). Summaries are always saved.
- **Combat summaries are kept forever by default;** a retention setting offers Forever (default), 1 year and 90 days.

Coordinator decisions (from the research):
- **Names.** Persisted: `tomato.history.encounter.CombatRecord` (card-sized, module `encounters`) and `CombatDetail` (buckets, sources, enemies, deaths, module `encounter-detail`), keyed by `recordingId`. Full detail: `<session>/combat-full/<uuid(recordingId)>.dps`. The existing `tomato.gui.dps.EncounterSummary` is untouched.
- **Split storage for speed.** Measured: a full summary is about 20–80 KB (dense 1 s buckets, 8 players); reading 1,200 full summaries takes about 300 ms warm, card-sized records about 40 ms. The feed and Home read only `encounters` (card records); the recap reads one `encounter-detail`.
- **What closes a fight.** A map change (today) and, new, **capture stop**: the close runs on the producer when it terminates. A fight in progress when the app exits or crashes is not saved (documented). After a capture restart in the same area the remainder is a separate, unlinked recording.
- **Buckets.** Damage over time is bucketed from the first tick (else the first hit), 1 s wide while the fight is ≤ 30 min; longer fights widen the bucket to `ceil(seconds / 1800)` s so a series never exceeds 1,800 values. Series: the verified local player plus the top 12 contributors (damage descending, then object id). Hits stamped before the first tick (time −1) count in the totals and are reported, not bucketed.
- **Enemies** are saved grouped by type (count, max HP when known, boss flag, damage, hits); bosses are also listed in the card record.
- **Several recordings in one run.** Cards, tiles and Home use the recording with the longest window (ties: the latest entry, then the recording id); the recap's Damage section offers a recording picker ("Recording 1 of 2 · longest").
- **Your row** is the recording's verified local row (`EncounterContext.localPlayerObjectId`). Without it, your DPS, rank, share and deaths are "—" with `RecordedEncounter.unavailableReason()`'s wording; another row is never substituted.
- **Damage totals.** The recap's Damage section uses the recording (all contributors). The run's own Inspect damage (`Visit.playerDamage`, inspected players only) appears only in the Players section, labeled "Inspect damage (inspected players only)".
- **Fame gained per run** (fixes the spec §8.5 "last − first" undercount): for each (session, account, character) series of fame samples in time order, a positive step from sample *a* to the next sample *b* is credited to *b*'s exact visit. A visit's gain is known only when every sample tagged with it has a predecessor in the same session and series; otherwise it is unknown (not zero). Negative steps are not gains.
- **Run outcome** has one rule for the feed, the recap and Home: Completed, Left, In progress, **App ended** (an unfinished visit of a session that ended without closing it, as Home shows today) and Unknown. The archive Table view keeps its own wording unchanged.
- **Party size** is the observed RotMG party (`Visit.rosterSize`); unknown is "—" ("party not observed"). Players seen in the dungeon (`inspectedPlayerCount`) appear in the Players section.
- **Exalt progress** shows only when positive and backed by the visit's evidence; otherwise it is omitted on cards and "—" on the recap tile.
- **The recap replaces the workbench as the way to read a run.** The archive Table view keeps the workbench details pane unchanged; the recap's Evidence section (Analyst) shows the same four workbench sections. Existing `RUNS` + visit routes (from Timeline, Loot, Inspect, …) keep opening the Table view on that row; Home's Recent runs and the feed's cards open the recap.
- **The feed reads saved history** (all sessions), 50 runs per page with "Load more"; the current run appears once its checkpoint is saved (about every 10 s). Day headers count the loaded runs and say so when the day continues below the loaded page.
- **S4 in P5a:** Home › Recent runs row → recap with the Damage section expanded (1 click); sidebar Runs → first completed card → recap (2 clicks).
- **Clear DPS Logs** keeps clearing only the in-memory list; its text says saved combat history is not deleted.

## Wave A

### Task 1: Combat summary model, builder and reader

**Owns:** see the file map. **Reads:** Q1 §1 (model, close, `DpsData`, `Entity`/`Damage`/`DamageSource`, `CombatMeterData`), §3 (SessionStore), §6.2 (sizes), §8 (risks R3, R5, R6, R7, R10).

- **`CombatRecord`** (`tomato.history.encounter`, public, Gson): `schemaVersion` (1), `recordingId`, `map` (MapInfo name) and `mapName` (display name), `enteredAt` (the context's `capturedAt`, MAPINFO entry), `Long startedAt` (first tick; null without ticks), `Long elapsedMs` (first to last tick; null without ticks), `Long firstHitAt`, `Long lastHitAt`, `Double windowSeconds` (the meter's shared first-to-last-hit window; null without hits), `String visitSession`, `String visitId` (both or neither), `Integer localObjectId` (verified local row only), `Integer localClassType`, `long totalDamage`, `long unattributedDamage`, `int contributors`, `List<PlayerLine> players` (every contributor, damage descending then object id), `int deaths` (death notifications in this recording), `int enemies`, `int enemyTypes`, `List<Boss> bosses`, `int hitsBeforeFirstTick`, `boolean fullDetail`. Methods: `VisitRef visit()` (validated; null unless both parts are non-empty), `PlayerLine local()` (the row with `local == true`, else null).
  - `PlayerLine`: `int objectId`, `String name` (nullable), `int classType`, `long damage`, `long hits`, `long maxHit`, `Long taken` (null when incoming damage was unavailable for that row), `boolean local`, `Integer deaths` (null when the name is unknown or shared by another row of this recording), `int rank` (1-based position in `players`).
  - `Boss`: `int type`, `String name`, `Integer maxHp` (null when unknown), `long damage`.
- **`CombatDetail`** (Gson): `schemaVersion`, `recordingId`, `long bucketOrigin`, `int bucketSeconds`, `List<Series> series` (`int objectId`, `boolean local`, `int[] values`), `List<PlayerSources> sources` (`int objectId`, `List<SourceLine>`: `String source` = `DamageSource` name, `long damage`, `long hits`, `List<ItemLine>`: `int itemId` (`DamageSource.itemOf`), `long damage`, `long hits`), `List<EnemyType> enemies` (`int type`, `String name`, `int count`, `Integer maxHp` (the largest known), `boolean boss`, `long damage`, `long hits`), `List<Death> deaths` (`String name`, `int graveIcon`).
- **`CombatSummaries`** (`tomato.gui.dps`, public final; it may use the package-private `CombatMeterData`): `static Result build(DpsData data)` with `record Result(CombatRecord record, CombatDetail detail)`. Rules: the decisions above (buckets, series, enemies grouped by type, local row, deaths inside the recording, unknown as null). Use `Damage.damage`, `DamageSource.of` and `DamageSource.itemOf` only (the shared `Projectile` objects are reset after close). Match `CombatMeterData`'s damage, hits, biggest hit, taken, window and share definitions exactly; ranks follow `MeterSummary`'s order. A `DpsData` without a context (legacy) gives `visitSession`/`visitId`/`localObjectId` null. Returns detached objects.
- **`CombatFacts`** (public, off the EDT only): `static void read(SessionStore store, List<SessionStore.SessionEntry> catalog, String scope, Consumer<CombatRecord> sink)` (skips records with `schemaVersion` > 1 or no `recordingId`; never throws for one bad file), `static CombatDetail detail(SessionStore store, String session, String recordingId)` (null when absent), `static CombatRecord longest(Collection<CombatRecord> sameRun)` (the tie rule above), and `static Map<VisitRef, List<CombatRecord>> byVisit(Collection<CombatRecord>)` (exact `VisitRef` equality; records without a visit are left out).
- **`SessionStore.readCheckpoint(String session, String module, String key, Class<T> type)`**: reads `<session>/<module>/<uuid(key)>.json` (the name `put` writes), off the EDT; `Optional.empty()` when absent.
- **`CombatFixtures`** (test, public): builders for synthetic `DpsData` (players, enemies, hits with sources and item ids, deaths, a context with or without a visit and a local id) reusing the `DpsInvestigationTest`/`MeterSummaryTest` helper style; `writeRecord(Path root, String session, CombatRecord)` and `writeDetail(...)` in the `put` layout; `writeLarge(Path root, int sessions, int runs)` that adds one record and one detail per run of `HomeHistoryFixture.writeLarge` (same session and visit ids, 8 players, 60 enemies, 150 s).

### Task 4: Auto-save, full detail, retention and Home's DPS

**Owns:** see the file map. **Depends on:** Tasks 1 and 3. **Reads:** Q1 §1.2, §1.7, §2, §3, §6, §8 (R1–R4, R11–R16, R19, R20).

- **Close hand-off (producer):** `TomatoData.clear()` keeps building the `DpsData` as today and additionally records it as the last closed encounter; after `clear()` returns (in `setNewRealm`, and in the new `captureTerminated()`), the producer passes it to `CombatAutosave.submit(DpsData)` (non-blocking). - **Capture stop:** new `TomatoData.captureTerminated()` (producer) runs the close half of `clear()` for the open encounter (context captured before the reset, as `clear()` does) and submits it. `CapturePublication.terminated(worker)` calls it for the current worker (it runs on the producer when the loop ends; in the start-failure path no encounter exists). `stopRequested` (EDT) never touches encounter state.
- **`CombatAutosave`** (`tomato.gui.dps`, public): one daemon worker "RealmShark combat history"; `submit` queues; the worker builds `CombatSummaries.build`, then `store.put("encounters", id, record)` and `store.put("encounter-detail", id, detail)`; when `CombatSettings.current().keepFullDetail()`, it writes `getSaveFile(false)` to `<current session>/combat-full/<uuid(id)>.dps` atomically and sets `record.fullDetail = true` before the put. Preview mode (read-only store) saves nothing. Failures are logged and never stop the worker; `flush(timeout)` for tests and shutdown.
- **`SessionStore`:** `Path currentDirectory()` (the writable current session folder; empty in preview) and `int deleteFiles(String session, String module, Predicate<Path> match)` (closed sessions only: refuses the current session and sessions locked by another instance, as `delete` does; returns the count).
- **`CombatRetention`** (`tomato.history.encounter`, public): `static Result prune(SessionStore store, CombatSettings.Values values, long now, Cancellation cancel)` deletes `combat-full` files older than `fullDetailDays` and, when `summaryDays` is set, the `encounters`, `encounter-detail` and `combat-full` files of records older than it (age from `enteredAt`, else the file time). `Result(int files, long bytes, int sessionsSkipped)`. Runs on the combat worker at startup (after the store opens) and after a Combat history setting changes; never on the EDT or producer.
- **Home's DPS from saved records:** `HomeArchive` adds `encounters` to its cached folders and reads card records for the sessions of the runs it shows; a run's DPS comes from `CombatFacts.longest` of its exact records, merged with this app run's in-memory recordings by `recordingId` (in-memory wins while present). Home's texts stay; the P2 note "current app run only" is no longer true and its wording is updated where shown.
- **Clear DPS Logs:** its confirmation/tooltip says it clears the in-memory list and does not delete saved combat history.
- **Storage measurement:** `CombatStorageMeasurementTest` builds real summaries from synthetic `DpsData` of three shapes (150 s / 8 players / 60 enemies; 600 s / 8 / 150; 3,600 s realm / 30 / 2,000), prints bytes per record and per detail, writes `CombatFixtures.writeLarge` beside `HomeHistoryFixture.writeLarge` (30 × 40), prints total bytes on disk and cold/warm times of `CombatFacts.read` (all records) and `HomeArchive.read`, and soft-asserts: a 600 s record ≤ 16 KB, its detail ≤ 64 KB, the large read warm ≤ 250 ms. The numbers go into the validation record.
- **Tests:** `EncounterIdentityTest` add beside (a map change saves a record with the exact `VisitRef` and local id; capture stop saves the open fight; a restart in the same area gives a second, unlinked record), `CombatAutosaveTest` (worker off the producer; preview saves nothing; full detail on/off; no debug packets in the file; a failing write does not stop later saves), `CombatRetentionTest` (age rules; current and locked sessions skipped; forever keeps summaries), `SessionStoreTest` add beside, `HomeArchiveTest`/`LiveHomeSourcesTest` add beside (DPS survives a restart; in-memory dedupe by id; unverified local stays "—").
