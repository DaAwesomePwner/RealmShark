# P4 Quests: Board and Planner Implementation Plan

> **For agentic workers:** implement with subagent-driven development: one fresh implementer subagent per task, in an isolated worktree, working test-first; the coordinator (Claude) reviews every task's diff and merges it. This is a **contract plan** (as P3b): it fixes the decisions, file ownership, names, signatures, behavior and the tests each task must add, and leaves the code to the implementer. Research notes with verbatim current code are the implementer's reference for existing APIs (see "Sources").

**Goal:** Restyle the Quests page (spec §6.5). The Board becomes painted quest cards (grouped by chest tier, type label or none; badges; rewards first; requirements with counts; a detail drawer) with the existing table kept as a Table view; the Planner becomes plan cards with reserved / covered / missing bars, an all-plans summary and the manual stock editor in a drawer, semantics unchanged; the tabs are titled Board and Planner; Home's Quests card opens the Board and tells uncaptured rewards apart from none.

**Not in P4 (user decision, 2026-09-28):** the expiry countdown (spec §6.5 "Expiry countdown", roadmap P4 items 1 and 5, open item O1). P4 adds no `QuestExpiry` parser, no expiration diagnostic, no countdown chip, no "expiring today" count and no "expiring soonest" ordering. The raw server expiration stays visible in the Board's Analyst detail. The countdown becomes its own later phase (see "Deferred scope").

**Architecture:**
- **Wave A (parallel):** the Board's pure models (Task 1), the Planner restyle with a stacked kit bar (Task 2), Home's Quests card honesty fix (Task 3).
- **Wave B:** the Board UI: cards, groups, summary, detail drawer, Cards/Table views, tab titles (Task 4).
- **Wave C:** Quests routes (Board and Planner as explicit, Back-restorable navigation) and the S3 click-path test (Task 5).
- **Wave D:** evidence, docs, validation record, final suite and JAR smoke (Task 6).
- Every view model is built off the EDT or from detached copies and applied on the EDT, as in P3. No persisted-format change: `Characters/plans.json` and the quest pin preferences keep their shapes.

**Tech Stack:** Java 17, Swing, FlatLaf 3.5.4, Gson 2.9.1, JUnit 4.13.2

**Spec:** `docs/superpowers/specs/2026-09-26-ui-ux-redesign-design.md`: §1 (honesty invariants; S3), §3.2 (Simple/Analyst), §4.4 (customizable tabs), §5.3, §5.6, §5.7 (components, filter bar, `DisplayValue`), §6.1 (Home Quests card), §6.5 (Quests), §7 (states), §9 (painted lists), §10 (accessibility).

**Depends on:** P3b merged (PR #23, merge `b559bca`).

**Sources (read before coding; verbatim current code with file:line):** research notes Q1 (quest data and the Board), Q2 (the Planner), Q3 (Home Quests card, S3, routes, P3b conventions) and Q4 (expiration and diagnostics), kept in the coordinator's scratchpad and handed to each implementer. ## Decisions recorded for this phase

User decisions (2026-09-28):
- **The expiry countdown is deferred** to its own later phase: no parser, diagnostic, chip, "expiring today" count or "expiring soonest" ordering in P4. When that phase adds the "Copy expiration samples…" diagnostic, its output includes the list's receipt time (UTC, rounded to the minute) beside the distinct raw strings and their counts.
- **Cards plus a Table view.** The Board shows cards by default; the existing quest table stays as a Table view (like Characters' Gallery/Table: the ⋯ menu offers the other view in Simple, a toggle shows in Analyst); one filter bar and search serve both.
- **Process:** subagent-driven development, Claude reviewing every task (as P3b).

Coordinator decisions:
- **Tab titles** follow the spec: "Board" (id `captured`) and "Planner" (id `plans`). Planner and Board texts that name the old titles ("Saved plans", "Captured quests") are updated.
- **Chest tier** of a quest for grouping: the highest tier among its reward names, using the existing `matchesReward` name rules, in the order Mighty > Epic > Standard > Beginner. A quest with rewards but no quest chest is "No quest chest"; a quest whose rewards were not captured is "Rewards not captured". Group order: Mighty, Epic, Standard, Beginner, No quest chest, Rewards not captured. Chest tier and type label stay independent axes.
- **Group by** offers Chest tier (default), Type label ("No type label" for unlabeled categories) and None. **Pinned first** is a toggle (default on) that orders pinned quests first within each group.
- **Cards are fixed-size.** A card reserves 4 reward slots and 4 requirement slots with a "+N" overflow; the full lists are in the detail drawer.
- **S3 in P4:** "pinned quests and what they reward" in ≤ 1 click: Home's Quests card lists pinned quests with their rewards (0 clicks), and one click opens the Board (the Board tab even when the Planner was last shown) with pinned quests first and their reward sprites. The "expire today" half of S3 moves with the countdown phase.
- **Raw expiration** shows only in the Board's Analyst detail (spec §6.5: "raw expiration in Analyst"); Simple shows none.
- **Planner cards** show each plan alone (reserved / covered / missing per requirement), and an **All plans** summary card shows the account's combined totals (`QuestPlanning.totals` over every plan), because per-card numbers each count the same unreserved stock. The Table view keeps today's multi-select combined totals.
- **Manual values** use the kit's existing `DisplayValue.manual` rendering ("1,240 (manual)"); P4 does not introduce the spec's ✎ glyph.
- **No new analytics:** no inventory "have it" check, no inferred readiness beyond `QuestPlanning`'s existing texts.

## Wave A

### Task 1: Board models (pure)

**Owns:** see the file map. **Depends on:** nothing in P4. No Swing.

```java
/** Chest tier of a quest from its reward names (the existing QuestGUI.matchesReward rules), highest first. */
enum QuestTier {
    MIGHTY("Mighty quest chests"), EPIC("Epic quest chests"), STANDARD("Standard quest chests"), BEGINNER("Beginner quest chests"),
    NO_CHEST("No quest chest"), NOT_CAPTURED("Rewards not captured");
    final String label;
    /** The highest tier among the rewards' names; NO_CHEST when none is a quest chest; NOT_CAPTURED when rewards are unknown. */
    static QuestTier of(QuestGUI.Quest quest, IntFunction<String> names);
}

/** One quest card: everything the painted card and the detail drawer show. Lists are immutable (List.copyOf). */
record QuestCardModel(String id, String name, boolean pinned, boolean repeatable, boolean completed, boolean choice,
                      String typeLabel, QuestTier tier, List<Item> rewards, boolean rewardsKnown,
                      List<Item> requirements, boolean requirementsKnown, String description, String rawExpiration) {
    /** An item id with its count (repeated ids in the packet mean quantity), its name and its tier label for the sprite border. */
    record Item(int id, int count, String name) {}
    /** "↻ Repeatable" or "One-time", plus "✓ Done" when completed. */
    List<String> badges();
    /** Card header for rewards: "You get", or "Pick 1 of N" when choice (N distinct reward items). */
    String rewardsTitle();
    static QuestCardModel of(QuestGUI.Quest quest, boolean pinned, String typeLabel, IntFunction<String> names);
}

/** The Board: groups of cards and the summary line. */
record QuestBoardModel(List<Group> groups, Summary summary) {
    enum GroupBy { TIER, TYPE, NONE }
    record Group(String key, String title, List<QuestCardModel> cards) {}
    /** total quests, pinned, repeatable, done; capturedAt epoch ms (0 unknown); stale per the page's existing rule. */
    record Summary(int total, int pinned, int repeatable, int done, long capturedAt, boolean stale) {
        /** "14 quests · 3 pinned · captured 14 min ago" (+ " · stale" when stale); "No quest list captured yet" when none. */
        String text(LongSupplier clock);
    }
    static QuestBoardModel build(List<QuestCardModel> cards, GroupBy by, boolean pinnedFirst, long capturedAt, boolean stale);
}
```
- Rewards and requirements aggregate repeated ids into counts, keeping first-seen order. A `null` list gives `rewardsKnown`/`requirementsKnown` false and an empty item list (the card says "not captured", never "none").
- Grouping by TYPE uses the user's label for the quest's category ("No type label" when unlabeled); by NONE gives one group titled "All quests". Groups keep the fixed order (tier order, then labels alphabetically, then "No type label"); empty groups are omitted. Within a group: pinned first when `pinnedFirst`, then the existing Board sort's order (the input order).
- `Summary.text` uses `KitFormat.relative` semantics with the injected clock (`KitFormat.relative` has its own static clock; use the same wording: "just now", "N min ago", …).

**Tests (new):** `QuestTierTest` (each tier by name; a choice quest with Mighty and Epic chests → MIGHTY; a plain "Quest Chest" → STANDARD; no chest → NO_CHEST; `null` rewards → NOT_CAPTURED; missing asset names "Unknown item #id" → NO_CHEST). `QuestCardModelTest` (count aggregation and order; choice title "Pick 1 of 3"; badges for the four repeatable/completed combinations; not-captured lists; the raw expiration kept verbatim, "" when not supplied). `QuestBoardModelTest` (group order and titles for each GroupBy; pinned first on and off; empty groups omitted; summary counts and text with a fixture clock, stale suffix, and the no-list text). `QuestFixtures`: synthetic `QuestData`/`QuestGUI.Quest` builders with item names (reuse the names in `QuestGuiTest`).
